# iRespond Challenges — Architecture, State Machines & Threat Model

## 1. Domain Overview & Source of Truth
`iRespond Challenges` is an internal first-class domain within the canonical `Atlasfsp/iRespond` repository (`services/api/internal/challenges`, `services/api/cmd/server/challenge_routes.go`, `services/api/migrations/0014_challenges_domain.sql`). It shares the same StratoID/OIDC authentication verifier, SS-13 resource policy boundary, RustFS create-only evidence pipeline, SS-24 privacy/consent model, SS-18 notification outbox, and PayCore financial settlement boundary as Needs and Action Projects.

## 2. Authoritative State Machines & Truth Invariants

| Aggregate | States | Critical Invariant |
|---|---|---|
| `challenge_programs` | `draft -> review -> scheduled -> registration_open -> active -> judging -> results_pending -> results_published -> archived / cancelled` | Cannot transition past `draft/review` without `current_rules_version >= 1` backed by **two distinct human approvals** (`challenge_rule_approvals`) for the exact `rules_sha256` digest and rubric weights summing to `10000` basis points. |
| `challenge_entries` | `draft -> applied / screening -> eligible / needs_information / ineligible -> accepted -> withdrawn / disqualified` | Minor or guardian-policy tracks start in `screening` with `guardian_consent_status = required` until a verified SS-24 receipt is recorded. Consent revocation blocks public disclosure and recalls public results. Eligibility review rejects self-review (`reviewer == lead_actor_id`). |
| `challenge_submissions` | `draft -> submitted -> under_review -> qualified / revision_requested / declined -> locked` | Final submission requires `now < round.closes_at` (server UTC) and a 64-hex `submission_sha256`. |
| `challenge_judge_assignments` & `challenge_scorecards` | Assignment: `proposed -> accepted -> completed / recused`; COI: `undisclosed -> no_conflict_declared / conflict_declared -> independently_cleared / recused`; Scorecard: `draft -> sealed -> voided` | Judges must be human (`principal.IsHuman()`). Scoring is blocked until COI is `no_conflict_declared` or `independently_cleared`. A judge **cannot** clear their own conflict. Sealed scorecards compute integer `total_basis_points` server-side from criterion weights summing to `10000` bps. |
| `challenge_decisions` & `challenge_appeals` | Decision: `draft -> reviewed -> approved -> published`; Appeal: `submitted -> admissibility_review -> investigating -> upheld / denied / remanded` | Publishing round decisions requires sealed scorecard quorum, independent human approval, and **zero open appeals** (`409 Conflict` if an appeal hold is active). |
| `challenge_sponsors`, `challenge_awards` & `challenge_prize_fulfillments` | Sponsor: `interest -> pledged -> provider_confirmed -> fulfilled`; Award: `nominated -> approved -> published -> revoked`; Fulfilment: `pending -> provider_initiated -> confirmed_delivered` | Sponsor `pledged` is never labelled settled funds and never grants judge authority. `award_approved` is distinct from `confirmed_delivered`. For `cash_provider`, `confirmed_delivered` requires verified PayCore reference and provider confirmation; client `paid=true` is ignored/rejected. |

## 3. Threat Model & Mitigations
1. **Cross-Tenant IDOR / Enumeration:** Every table is composite-keyed by `(tenant_id, program_id)` or `(tenant_id, id)`. Foreign-tenant access returns scope-safe `404 Not Found` or `403 Forbidden` without leaking resource metadata.
2. **Self-Dealing & Conflict of Interest:** Self-second-approval of rules, self-eligibility review, self-judging, judge self-clearance of COI, and self-appeal resolution are rejected in the domain service and tested in `services/api/internal/challenges/service_test.go`.
3. **Minor Safeguarding & Privacy Redaction:** Guardian details (`guardian_subject_ref`, `ss24_consent_receipt_ref`) and restricted rationales are withheld from public projections. Revoking guardian consent immediately redacts the entry from public results.
4. **Unverified Cash Settlement Spoofing:** Clients cannot mark cash awards as paid (`paid: true` is rejected). Only verified PayCore references with provider confirmation timestamps can transition a `cash_provider` fulfilment to `confirmed_delivered`.
5. **AI / Service Principal Escalation:** Non-human principals (`actor_type != "human"`) are rejected on all human-only endpoints (rule approval, eligibility decision, COI declaration/clearance, scorecard sealing, decision publication, appeal resolution, award approval, and prize fulfilment verification). Optional AICO assistance is disabled by default (`AICOEnabled = false`) and proposal-only.
